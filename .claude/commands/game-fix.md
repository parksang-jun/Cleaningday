제보: $ARGUMENTS

AGENTS.md 의 규칙을 따른다. 순서를 건너뛰지 않는다.

1. **제보 나누기** — 제보에 문제가 여러 개면 하나씩 나눠 적는다. 각 문제에 "사용자가 한 일 / 기대한 것 / 실제로 일어난 것"을 한 줄씩.
2. **어느 버전인가** — 스크린샷·설명으로 사용자가 쓰는 버전을 추정하고, `git log --oneline` 에서 그 출시 빌드 커밋을 찾는다. `main` 과 다르면 그 커밋의 코드에서 확인한다(`git worktree add`).
3. **재현** — 문제마다 실패하는 단위 테스트나 엔진 시뮬레이션을 만든다. 네이티브 플러그인이 얽혀 있으면 `node_modules` 의 iOS/Android 소스를 읽어 실제 동작을 확인한다. 재현이 안 되면 추측으로 고치지 말고 무엇을 더 알아야 하는지 보고하고 멈춘다.
4. **원인 한 문장** — 각 문제의 원인을 한 문장으로 적는다. 여러 증상이 한 원인이면 묶는다.
5. **수정** — tdd-guide 에이전트로: 실패 테스트 → 최소 수정 → 통과. 문구를 바꿨으면 ko·en·ja 를 같이 고친다.
6. **검사** — `npx tsc --noEmit` → `npm test` → `npm run build` → `npm run e2e` → `npx cap sync`. 빌드가 깨지면 build-error-resolver 에이전트.
7. **리뷰** — code-reviewer 에이전트에 변경분을 맡기고, 지적 중 실제 결함만 고친다. 광고·결제·개인정보를 건드렸으면 security-reviewer 도.
8. **빌드 번호** — 앱에 들어가는 수정이면 iOS `CURRENT_PROJECT_VERSION` 과 Android `versionCode` 를 1씩 올린다.
9. **커밋·보고** — 커밋 메시지에 제보·원인·수정을 적는다. 보고는 한국어로: 문제별 원인과 수정, 통과한 검사 수, **실기기에서 아직 확인 못 한 것**, 지금 쓰는 사용자가 당장 할 수 있는 임시 방법, 운영자가 Mac 에서 할 일(복사해 붙일 명령).
