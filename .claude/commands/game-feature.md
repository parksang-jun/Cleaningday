요청: $ARGUMENTS

AGENTS.md 의 규칙을 따른다.

1. **계획** — planner 에이전트로 계획을 세운다. 구조를 크게 바꾸면 architect 에이전트도. 계획에는 다음을 넣는다: 바뀌는 파일, 플레이어가 느끼는 변화, 난이도·보상·광고 노출에 주는 영향, 되돌리는 방법.
2. **승인이 필요한가** — 광고 빈도, 가격, 보상 수치, 스토어 제출이 바뀌면 여기서 멈추고 승인 요청을 적는다. 아니면 계속.
3. **구현** — tdd-guide 에이전트로 규칙(`src/game/`)부터 테스트와 함께, 그다음 화면(`src/render/`, `src/main.ts`), 마지막에 문구(ko·en·ja).
4. **눈으로 확인** — 화면이 바뀌었으면 Playwright 로 해당 판을 캡처해 확인하고, 캡처를 보고에 첨부한다.
5. **균형** — 판·오염·도구를 바꿨으면 `balance.test.ts` 와 봇 기준 시간이 맞는지, 막히는 판이 없는지 확인한다.
6. **검사·리뷰** — `/game-fix` 의 6~7단계와 같다. e2e 가 새 기능 때문에 깨지면 테스트를 지우지 말고 새 흐름에 맞게 고친다.
7. **보고** — 무엇이 달라졌는지, 한계(이번에 안 한 것), 실기기에서 조정이 필요한 수치를 적는다.
