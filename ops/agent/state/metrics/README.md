# 지표 파일 넣는 곳 (state/metrics/)

제품개선팀(루틴 D)·운영팀(루틴 A)·광고팀(루틴 E)이 실행할 때마다 이 폴더를 읽는다. **파일이 없으면 보고서에 "지표 없음"이라고 적고, 숫자를 지어내지 않는다.**
받은 파일은 고치지 않고 그대로 둔다. 개인정보(이름·메일·기기 식별자)·결제·계좌 화면은 넣지 않는다.

## 파일 이름

`원천-내용-기간.csv` — 예: `appstore-retention-2026-11-17_2026-11-30.csv`

| 원천 | 내용 | 받는 곳 | 이것으로 확인하는 것 |
|---|---|---|---|
| `appstore-` | 설치(첫 다운로드)·세션·사용 기기·유지율(1일·7일)·충돌 — 일별, 가능하면 국가별 | App Store Connect 앱 분석 내보내기 | 리텐션 게이트(D1 30%·D7 10%), 빌드별 전후 비교 |
| `appstore-search-` | 노출·제품 페이지 조회·전환율 — 일별 | App Store Connect 앱 분석 | 스토어 문구(aso-2026-11) 반영 전후 2주 비교 |
| `play-` | 설치·제거·평점·충돌(ANR) — 일별 | Play Console 통계 내보내기 | 안드로이드 출시 뒤 같은 비교 |
| `admob-` | 날짜·국가·앱·형식(배너/전면/보상형)별 요청·노출·예상 수익·eCPM | AdMob 보고서 내보내기 (결재 revenue-data-export) | 국가별 수익, 광고 형식별 비중, 빌드 전후 노출 변화 |
| `reviews-` | 날짜·별점·본문·버전(작성자 이름은 지운다) | 스토어 리뷰 내보내기 또는 붙여넣기 | 피드백 대장(feedback.csv) 기록 |
| `sns-` | 게시물별 조회·유지율·프로필 방문·링크 클릭 | 인스타그램 인사이트(화면 숫자를 옮겨 적어도 됨) | 홍보 영상 성과(campaigns.csv) |
| `stages-` | 판 번호별 시작·통과·실패·포기 횟수, 평균 걸린 시간, 재시도 | **지금은 받을 방법이 없음** — 아래 참고 | 판별 이탈, 별 관문에서 멈춘 비율, 제한 시간 조정 |

## 판별 지표(`stages-`)가 없는 이유

게임은 판 시작·통과·실패·포기·힌트·상점 구매 같은 기록 40여 종을 남기지만(`src/analytics.ts` 의 `track`), **기기 안에서만 쌓이고 밖으로 보내지 않는다**(받는 쪽은 운영자 화면 집계 `src/ops.ts` 하나). 스토어 통계에는 판 번호가 없다.
그래서 "몇 판에서 그만두는가", "광고 직후 이탈", "별 관문에서 멈춘 비율"은 지금 구조로는 알 수 없다. 얻는 방법은 결재 `stage-metrics-source` 에 올려 두었다.

`stages-` 파일이 생기면 열 이름은 이렇게 맞춘다: `date,build,level,starts,completes,fails,quits,avg_sec,retries,stars_avg`

## 전후 비교 기준 (효과 확인용)

| 빌드 | 들어간 것 | 비교할 숫자 |
|---|---|---|
| 1.1 | 도구 강화·별 관문, 광고 40코인 건너뛰기, 처음 6판 광고 유예 | 1일 유지율, 세션당 전면 광고 노출 |
| 1.2 / 1.2.1 | 새 오염 5종, 힌트 수정, 보상 광고 멈춤 수정, 글씨·오염 모양 | 보상형 광고 노출(멈춤 수정 전후), 평점·리뷰 |
| 빌드 18~22 | 화면 확대, 전용 도구, 상점 구매 표시, 닦이는 손맛 | 세션 길이, 1일·7일 유지율, 리뷰의 "안 닦인다" 언급 |

출시일(빌드별)을 함께 적어 주면 전후 2주를 나눠 비교한다.
