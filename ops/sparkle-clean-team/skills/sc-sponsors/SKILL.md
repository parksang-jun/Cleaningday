# 브랜드 제휴·스폰서 영업 — Sparkle Clean

이 게임의 스폰서 상품은 **"성능이 진짜인 광고"**다. 실제 청소 도구·세제 회사의 제품이 게임 아이템으로 들어가고, 게임 속 세척력은 광고주가 낸 **시험 성적서만으로** 정해진다(같은 방법으로 시험한 일반 기준 제품 대비 비율, 0.5~1.8배로 제한). 근거가 없는 항목은 일반 제품과 같고, 라벨의 사용 금지 재질은 게임에서도 손상을 일으키며, 모든 스폰서 아이템에는 "광고" 표시와 근거 화면이 붙는다. 광고비로 성능을 살 수 없다는 점이 이 상품의 신뢰이자 셀링 포인트다.

## 시작 전

1. 코드의 현재 구현을 읽는다: `src/game/sponsor.ts`(타입·`REFERENCE_REMOVAL`·`REFERENCE_COVERAGE`·`RATIO_MIN/MAX`·`performanceRatios`·`validateSponsor`·`toItemSpec`·`SAMPLE_SPONSORS`), `src/game/items.ts`(`activeSponsors`), `src/main.ts`(`openShop`·`openEvidence`·`renderToolbar`), `src/game/catalog.ts`(도구·세제 기준 계열, 표면 8종, 화학 계열).
2. 게임 단계 확인(`sc-pm` 로드맵): 소프트런치 전이면 영업 대신 **준비**(기준 제품 실측, 제안서, 계약서 초안, 원격 설정·노출 이벤트 개발 요청)만 한다. 노출 근거 없는 판매는 하지 않는다.
3. 참고 문서: `references/onboarding-spec.md`(제출 패키지·환산·한계), `references/review-checklist.md`(라이브 전 검수), `references/sales-kit.md`(타깃·피치·가격 모델·메일), `references/advertiser-report.md`(광고주 리포트).

## 업무별 산출물

### 1. 광고주 발굴·리스트
- 대상: 게임 아이템 계열(걸레/극세사, 스펀지, 솔, 진공청소기, 고압세척기 / 다목적 세정제, 기름때 제거제, 물때 제거제, 곰팡이 제거제)에 맞는 제품을 가진 회사. 우선순위: 국내 중소·중견 브랜드(온라인 D2C 중심, 숏폼 마케팅 적극) → 해외 진출 브랜드 → 대기업(소프트런치 데이터 확보 후).
- 리스트 표: 회사 / 제품 / 게임 계열(base) / 보유 시험 성적서 여부(웹·상세페이지에서 확인되는 범위) / 담당 채널 / 우선순위 / 상태. 실제 회사 조사는 웹 검색으로 하되, 확인 안 된 사실(성적서 보유 등)은 "미확인"으로 쓴다.
- 문서·예시에서 실제 회사를 샘플로 쓰지 않는다(예시는 `Example Clean Co.(가상)` 형식).

### 2. 제안·영업
- 원페이저·메일(`sales-kit.md`): 문제(청소용품 광고는 "써봐야 안다") → 해결(게임 속에서 제품의 실제 강점을 직접 체험) → 근거 화면·광고 표시로 신뢰 → 지표·가격 옵션 → 다음 단계(서류 목록).
- **반드시 미리 말할 것**: ① 성적서가 기준 제품보다 낮으면 게임에서도 **기준보다 약하게** 나온다, ② 근거 없는 오염·특징은 반영되지 않는다, ③ 라벨 주의 표면에 쓰면 게임에서 손상이 난다, ④ 성능 상향·노출 조작 요청은 받지 않는다. 이를 숨기고 계약하면 라이브 직전 분쟁이 난다.

### 3. 서류 접수·성능 환산 시뮬레이션
- 제출 패키지 체크(`onboarding-spec.md` §1) → 누락 목록 회신.
- 환산표 작성: 오염별 제출 제거율 / 기준 제거율 / 비율(클램프 전·후) / 게임 수치(도구 effect·radius, 세제 mult) / 반영 안 되는 항목과 이유. 수치는 손계산이 아니라 코드로 검증한다 — `sc-dev` 와 함께 `src/game/game.test.ts` 에 해당 제품 케이스(검증 통과·환산값·"기준보다 빨리/느리게 닦임" 시뮬레이션)를 추가해 `npm test` 로 확인.
- 해당 계열 스테이지에서 봇 시간 비교(기준 제품 vs 스폰서 제품)를 광고주에게 보여줄 "게임 속 체감" 근거로 쓴다(봇 기준임을 명시).

### 4. 라이브 전 검수
- `review-checklist.md` 전 항목 통과 + 담당 2인 확인(사용자 + Claude 검토 기록). 하나라도 미통과면 라이브 불가.
- 통과 시 `sc-dev` 에 원격 설정(또는 빌드) 반영 요청: `SponsorProduct` JSON, 캠페인 기간, 노출 범위(앱만/포털 제외).

### 5. 가격 제안
- 모델: 캠페인 고정 스폰서십 / 툴바 노출 CPM / 제품 페이지 CPC / 혼합 — 장단점과 필요한 측정(`sales-kit.md` §4). **요율은 모두 TODO**: 시장 단가를 웹으로 조사하고 자사 노출 데이터가 생긴 뒤 사용자가 결정한다. 임의 숫자를 견적으로 내지 않는다.

### 6. 광고주 리포트
- 캠페인 종료 또는 월 1회, `advertiser-report.md` 형식. 수치는 `sc-analytics` 가 산출한 집계만(기기·사용자 단위 데이터 제공 금지). 측정 이벤트가 없는 항목은 "측정 불가"로 표기.

### 7. 종료·갱신
- 캠페인 종료일 지나면 `validateSponsor` 가 자동 비노출(`campaign_inactive`). 갱신 시 성적서 유효성(시험일 경과, 제품 리뉴얼 여부) 재확인.

## 원칙

- 성능은 판매 대상이 아니다. 광고주별 수치 조정, 근거 없는 상향, 경쟁 제품 하향, 기준 제품 값 변경을 통한 우회는 모두 금지. `RATIO_MIN/MAX`·`REFERENCE_*` 변경은 모든 광고주에게 동일 적용되는 운영 정책 변경이며 PM 승인 사항.
- 우월·최고·1위·"100% 제거"·"무독성" 같은 표현은 근거 범위 밖이면 쓰지 않는다(표시광고법 실증책임 — 세부 요건 확인 필요). 근거 화면의 표현은 "같은 방법으로 시험한 일반 기준 제품 대비 n%"로 한정.
- 법률(표시광고법·생활화학제품 표시·계약)은 정보 제공까지, 계약·최종 문구는 전문가 검토를 권한다. 조항 번호·요율은 확인된 것만 쓰고 나머지는 `확인 필요`/`TODO`.
- 아동 유입 가능성을 고려해 세제 광고 문구는 어린이에게 사용을 권하는 표현을 쓰지 않는다("아이도 쉽게" 등 금지).
- 한국어로 작성, 광고주 대상 문서는 요청 시 영어 병기.
